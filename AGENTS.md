# Инструкции для ИИ-агентов

Этот файл применяется ко всему репозиторию OpenCluely-fork. Если в подкаталоге
появится свой `AGENTS.md`, учитывай его для файлов этого подкаталога. Явные
инструкции пользователя имеют приоритет над рекомендациями этого документа.

## Как работать

- Общайся с пользователем по-русски, если он не попросил другой язык.
- Доводи порученную задачу до проверяемого результата. Не спрашивай повторное
  разрешение на уже порученные обычные изменения.
- Перед правками проверь `git status --short`. Сохраняй чужие изменения;
  не откатывай и не перезаписывай их ради своей задачи.
- Сначала прочитай затронутый код и его вызывающие стороны. Ищи через `rg`.
- Делай небольшие изменения в пределах задачи. Не совмещай исправление ошибки
  с массовым форматированием, обновлением зависимостей или сменой архитектуры.
- Следуй стилю изменяемого файла: в репозитории смешаны одинарные и двойные кавычки.
- В завершении укажи результат, выполненные проверки и оставшиеся ограничения.
  Различай чтение кода, изолированную проверку и настоящий запуск приложения.

## Что это за проект

Настольное приложение на Electron, JavaScript и CommonJS. Интерфейс состоит из
HTML-страниц с CSS, встроенными скриптами и файлами из `src/ui/`. React, TypeScript
и сборщика интерфейса сейчас нет. AI-провайдеры — Gemini, OpenAI-совместимый API и
Cloudflare Workers AI. Распознавание речи — Azure Speech, локальный Whisper или
Cloudflare Whisper. Запись использует системный аудиовыход, без перехода на микрофон.
Whisper использует отдельный Python-процесс с PyTorch.

| `src/core/system-audio-session.js` | Разрешение Windows loopback для основного окна |

| `src/core/first-run.js` | Создание конфигурации и состояние первого запуска |
| `src/core/whisper-installer.js` | Обнаружение, установка Whisper и загрузка моделей |

| `src/managers/session.manager.js` | Контекст диалога и события сессии |

| `src/services/openai-compatible.service.js`, `src/services/ai-http.js` | OpenAI / Workers AI Chat Completions, HTTPS и SSE |
| `src/services/cloudflare-speech.service.js` | Облачная транскрипция Whisper через REST API |
| `src/services/system-audio.service.js`, `src/ui/system-audio-capture.js` | Монитор выхода Linux и захват аудио в renderer |
| `src/services/capture.service.js` | Захват экрана и обрезка изображения |
| `src/services/speech.service.js` | Провайдеры речи, запись, VAD и транскрипция |
| `src/services/whisper-worker.service.js` | Запуск Python-worker и обмен JSON-сообщениями |
| `scripts/whisper_worker.py` | Загрузка модели, транскрипция, освобождение GPU-памяти |
| `index.html`, `src/ui/main-window.js` | Основная панель приложения и захват аудио в renderer |

Основной поток: действие в UI → preload/IPC → main → сервис → событие IPC → UI.
Для голосового ввода дополнительно работают сегментация по паузам и объединение
фрагментов транскрипции перед запросом к модели. Захват экрана отправляет изображение
в Gemini напрямую; имена некоторых методов и событий всё ещё содержат `OCR`.

## Команды и окружение

Сначала проверяй доступность инструментов и зависимостей. Используй `package-lock.json`;
для воспроизводимой установки — `npm ci`. Установка запускает `postinstall` Electron
и может требовать сети. Python/Whisper и его модели устанавливаются отдельно.

- `npm start` — запуск из исходников через кроссплатформенный `scripts/run-electron.js`.
- `npm run dev` — запуск с `--no-sandbox --disable-gpu`; это режим отладки.
- `npm run test-speech` — диагностика настроенного провайдера речи, не набор unit-тестов.
- `npm run pack -- --publish never` — упаковка без создания установщика и публикации.
- `npm run build:win -- --publish never` — сборка Windows.
- `npm run build:linux -- --publish never` — сборка Linux.
- `npm run build:mac -- --publish never` — сборка macOS; текущий CI её не выполняет.
- `node --check <file.js>` — проверка синтаксиса без исполнения файла.
- `npm test` — регрессионные тесты провайдеров, настроек и аудио, без настоящих ключей.
- `npm run check:syntax` — синтаксис JS и встроенных скриптов HTML.
- `npm run test:ui` — скрытые окна Electron с тестовыми провайдерами.
- `node scripts/run-electron.js scripts/check-cloudflare-connection.js` — ручная
  проверка Cloudflare с сохранёнными ключами Windows или явно переданным путём `.env`;
  применяет сетевые настройки приложения, отправляет два фиксированных тестовых
  запроса, не выводит ключи и историю.
- `node scripts/run-electron.js scripts/test-system-audio.js` — Windows loopback probe;
  кратко запрашивает аудиопоток и освобождает его, ничего не сохраняет.
- `<Python окружения Whisper> scripts/check-whisper-gpu.py --device cuda` —
  реальная проверка вычислений CUDA без загрузки модели. `--smoke --model-dir <cache>`
  проверяет существующие веса на искусственной тишине без записи и скачивания.
- `<Python окружения Whisper> tests/whisper_worker_test.py` — тесты Python-worker.
- `node scripts/run-electron.js scripts/check-interview-prompts.js` — три фиксированных
  вопроса для ручной проверки промптов через настроенный OpenAI/Cloudflare API.

`npm start` и `npm run dev` работают в Windows PowerShell; `clean` пока использует
Unix-команду `rm -rf`. После установки зависимостей можно запустить
Electron непосредственно из PowerShell:

```powershell
Remove-Item Env:ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue
& .\node_modules\.bin\electron.cmd .
```

`setup.sh` рассчитан на Bash и выполняет установку, настройку окружения и при
обычном запуске открывает приложение. Не используй его как безобидную проверку.
Не запускай `release` для проверки изменения. Артефакты сборки находятся в `dist/`.

## Правила реализации

- Сохраняй `nodeIntegration: false` и `contextIsolation: true`. Новые возможности
  renderer проводи через узкие методы preload; проверяй отправителя и входные данные
  IPC в main. Не передавай привилегированные Electron-объекты в renderer.
- При изменении IPC проверяй всю цепочку: обработчик main, метод preload, фактически
  загружаемый UI, формат аргументов и отписку от событий.
- Для streaming сохраняй связь начала, фрагментов, завершения и ошибки через
  `messageId`. Учитывай сбой после частичного ответа, повтор запроса, параллельные
  источники ввода и очистку сессии во время генерации.
- Освобождай таймеры, слушатели, аудиопотоки, временные файлы и дочерние процессы
  при остановке и закрытии. Не скрывай сбои пустыми `catch` без причины.
- Не добавляй обход проверки TLS. Проверяй безопасность HTML, URL и Markdown
  перед вставкой внешнего содержимого в DOM.
- В Electron AI-запросы используют `net.fetch` с системным прокси. Не заменяй
  его прямым Node HTTPS без проверки прокси-сценария. Для Gemma 4 на Cloudflare
  отключено скрытое reasoning; не возвращай тесту соединения лимит 64 токена.
- Не записывай API-ключи, аудио, скриншоты и полные диалоги в новые логи.
  Не выводи содержимое пользовательского `.env` и не добавляй секреты в Git.
- `prompts/_interview.md` задаёт общий стиль коротких естественных ответов для
  активных профилей. Не переопределяй его требованием всегда давать длинный ответ
  в голосовых/скриншотных обёртках. Язык кода не должен менять язык пояснений.
- Проверяй Whisper в Python-окружении выбранного CLI. `nvidia-smi` и
  `torch.cuda.is_available()` недостаточны для доказательства работы inference.
  Явный `cuda` не должен скрыто переходить на CPU, в том числе в запасном CLI.
- Для новых параметров проверяй значения по умолчанию, чтение окружения,
  сохранение настроек, UI и `env.example`. Следуй разрешению `ENV_PATH` в `main.js`;
  не создавай второй независимый путь хранения настроек.
- Учитывай запуск из исходников и упакованного приложения. Установочный каталог
  может быть недоступен для записи; пользовательские данные храни в подходящем
  каталоге приложения. Проверяй доступность ресурсов внутри ASAR и `asarUnpack`.
- Учитывай Windows, macOS и Linux. Для дочерних процессов на Windows используй
  `windowsHide: true`, когда окно терминала не нужно пользователю.
- Меняя захват и позиционирование, учитывай идентификаторы мониторов, DPI,
  несколько экранов и отрицательные координаты.
- Сохраняй язык и визуальные соглашения существующего UI. Не добавляй новый
  UI-фреймворк или провайдера в рамках посторонней задачи.
- Не редактируй встроенные библиотеки в `lib/` без необходимости. При изменении
  зависимостей обновляй lockfile вместе с `package.json`.

## Проверка изменений

В проекте есть `npm test`, `check:syntax` и отдельная проверка интерфейса Electron.
Линтера пока нет. Выбирай проверки по изменению, не заявляй несуществующие команды.

- Для JS запускай `node --check` на изменённых файлах. Для встроенных скриптов
  HTML отдельно проверяй синтаксис, например через `vm.Script`; проверка `.js`
  не покрывает содержимое HTML.
- Для исправлений логики используй небольшой воспроизводящий сценарий или
  регрессионный тест: контекст диалога, маршрутизация событий, повторы, выбор экрана.
  Для простых изменений документации специальные тесты не нужны.
- При проверках с импортом singleton-сервисов учитывай побочные эффекты: запись
  логов, инициализацию SDK и запуск внешних процессов. По необходимости изолируй
  код и подменяй зависимости.
- При доступном GUI проверь затронутый пользовательский сценарий. Запросы к AI,
  микрофон и загрузку моделей запускай только когда это требуется задачей.
- Проверяй упаковку, если меняешь пути ресурсов, установку или конфигурацию сборки.
  После работы проверь `git diff --check` и итоговый diff.

## Известные особенности, которые нужно перепроверять

Это ориентиры для поиска, а не поручение исправить всё при каждой задаче.
После исправления обновляй соответствующий пункт.

- `src/ui/chat-window.js` существует, но `chat.html` сейчас использует встроенный
  скрипт. Наличие обработчика в отдельном JS-файле не означает, что он выполняется.
- `chat.html` и `llm-response.html` отображают streaming-фрагменты по `messageId`.
  Частичный ответ показывается как текст, Markdown и кнопки копирования применяются
  при завершении. Проверяй отсутствие дублей, параллельные ответы, ошибки и очистку.
- История UI сохраняется в `localStorage`, история модели — в памяти main.
  Их восстановление после перезапуска не синхронизировано.
- Объединение событий в `session.manager.js` может терять содержимое разных
  сообщений. Перед изменением обслуживания истории проверяй сохранность диалога.
- Методы обработки изображения принимают историю, но сейчас не включают её
  в запрос. Текстовые запросы используют ограниченное число последних событий.
- `capture.service.js` выбирает источник по разрешению; экраны одинакового размера
  могут перепутаться.
- Конфигурация Tailwind и `src/input.css` остались от исходного проекта, но нет
  сборки Tailwind и зависимости. Основная панель использует inline CSS и `common.css`.
- На Windows аудио захватывается через loopback; Linux требует `parec`, а macOS
  с Electron 29 — явно настроенный виртуальный loopback-вход. Не добавляй скрытый
  переход на микрофон при ошибке системного захвата.
- Проверка `desktopCapturer.getSources()` отслеживает доступность захвата,
  а не начало демонстрации экрана другим приложением.
- `src/core/network-session.js` сохраняет существующее безусловное принятие
  сертификатов Gemini; не распространяй этот обход. Для остальных доменов
  используй стандартную проверку Chromium (`-3`); `-2` отклоняет соединение
  и вызывает `ERR_FAILED` у Cloudflare и OpenAI.
- README, `package.json` и `LICENSE` содержат разные обозначения лицензии.
  Не выбирай лицензию самостоятельно в рамках технического изменения.
- README может описывать планируемые или неполные возможности. Утверждения
  о поведении подтверждай по коду и проверкам.
